# LanLink 局域网远控

一个只给自己用的 Windows 局域网远程控制工具：同一 WiFi/路由器下，电脑 A 可以看到并操作电脑 B 的桌面，支持剪贴板双向同步、A 向 B 发送文件、断线自动重连。被控端连接 VPN 后，只要 VPN 没有禁止本地局域网访问，A 仍然可以通过 B 的局域网 IP 直连。

- 单文件 exe，无需安装、无需服务、无需驱动
- 控制端/被控端共用同一个 exe，用 `--agent` 区分
- 原生 Rust + egui，屏幕采集走 GDI，键鼠注入走 SendInput
- 默认端口：TCP `47800`（控制/画面/文件），UDP `47801`（局域网发现）
- 当前版本：v4（协议版本 4）

### v4 改了什么

1. **界面文字看得清了**：上一版把「深色视觉」设成了依赖系统主题的一份样式，而用户 Windows 是浅色主题——程序启动后主题一刷新，整个界面就变成浅色（深灰字 #434343），却又露出近黑的面板底色，于是「黑底深灰字」。现在内置一套**自带调色板**（正文 `#E9EDF5`、次要 `#A3ADBF`，底色 `#0F1116`），主题固定为深色并同时写进 dark/light 两份样式，所有面板（顶栏/底栏/中央/卡片）都显式画底色，不再透出默认清屏色；正文从 12.5px 加到 15.5px、标题 22px，按钮内边距和行距也一起放大。
2. **键鼠「突然失灵」有自愈机制了**：根因是旧代码把「窗口是否聚焦」当成总开关——`InputState::focused` 一旦卡在 false（切全屏、Alt+Tab、系统弹窗、远程桌面抢焦点等都可能触发），键盘和鼠标会**一起**被丢弃，而且这个标志既不随重连重置，也不随点画面恢复。现在的处理是：
   - 删掉这条总开关，鼠标事件继续转发；键盘改用「真实焦点 **或** 用户点过本窗口的闩锁」判断，点画面时会主动 `ViewportCommand::Focus` 把焦点抢回来；
   - 控制端每 500 ms 发一次 `InputProbe`，被控端回 `InputStatus`（会话号、收到数、注入成功数、失败数）；控制端据此判断「指令到底有没有进去」，而不是靠猜；
   - 检测到「你一直在操作，但被控端计数 1.5 秒没动」或「注入被系统拒绝」时，界面顶部弹出红条，并且**自动修复**：先软修复（让被控端释放所有按键 + 重新对齐键鼠状态 + 重新获取焦点），连续两次无效则硬修复（立刻断线重连）；
   - 手动兜底：**F8 = 修复键鼠**、**F9 = 立即重连**，工具栏上也有这两个按钮；状态栏常显「键鼠 注入 N」——数字在涨说明事件确实到了被控端。
3. **重连一定拿到干净会话**：旧版被控端用 `busy` 标志「已经有控制端就拒绝新连接」，而旧连接可能卡在读写上十几秒才超时退出，这段时间里重连要么被拒、要么连上了但状态是脏的——这正是「断开重连还是不能操作」。现在改成**新会话顶掉旧会话**：新连接进来立刻 `shutdown` 旧 socket、清空被控端按住的键，会话号 +1；控制端看到会话号变化会把健康计数清零重算。被控端读超时也从 15 秒缩到 8 秒。

### v3.1 改了什么

1. **Ctrl+C / Ctrl+X / Ctrl+V 真正修好了**：根因不在被控端，而在控制端的事件层——egui 在窗口层就把这三个组合键转成了「复制/剪切/粘贴」事件，**不再产生普通按键事件**，所以 v3 里这三个键一个都没转发出去（这也解释了为什么其他 Ctrl 组合都正常、只有这三个不行）。现在把这三个事件翻译回真实的 Ctrl+C/X/V 注入，按下顺序保证是「Ctrl 按下 → 字母按下 → 字母抬起 → Ctrl 抬起」。
2. **注入的按键带上真实扫描码和左修饰键虚拟码**（Ctrl=`0xA2`、Shift=`0xA0`、Alt=`0xA4`，扫描码用 `MapVirtualKeyW` 补上）：Chromium 系应用（Chrome、Electron、VS Code、网页输入框）用扫描码填 `KeyboardEvent.code`，读扫描码或 `GetAsyncKeyState(VK_LCONTROL)` 的程序也才认得出这是真的 Ctrl。
3. **粘贴前补推剪贴板**：按 Ctrl+V 时强制重读本地剪贴板并立刻推送一次，刚连上新连接时也补推一次，避免粘到重连前的旧内容。
4. 新增开发者诊断开关 `--test-inject`：往当前前台窗口注入 F24 + 一段文本 + Ctrl+A + Ctrl+C，把每一步结果写进 `_inject_result.txt`，可以单独验证注入链路。

### v3 改了什么

1. **只看画面模式**：控制端顶部一键切换「只看画面」，切过去后完全不往被控端发键鼠事件，被控端也会立刻释放所有按下的键；被控端回一条确认消息，界面能看到状态。
2. **点击不再误触发右键**：键鼠改成按事件处理（谁按下的才转发、才抬起），画面外按下/抬起、窗口失焦、Alt+Tab 之类的事件不再让远端按键状态错位——以前“点一下别处就在被控端冒出右键”就是这个原因。
3. **Ctrl+C / Ctrl+V 更可靠**：修饰键改成跟着每个按键事件自己的 `modifiers` 快照按顺序同步，不再用整帧结束后的最终状态，因此不会出现“只发出裸 C”的情况；剪贴板轮询从 250ms 降到 80ms，并支持粘贴/复制时立即推送。
4. **帧率与延迟**：画面改成脏矩形 + 局部纹理上传（不再每帧 memcpy 整块 1080p 画布再重传整张纹理），采集线程不再 1ms 忙等，编码按变化比例自适应降质量；双屏机器可加 `--primary-only` 只共享主屏，实测 3840x1080 的 16.8 fps → 1920x1080 的 36.2 fps。
5. **连接更稳**：3 秒一次 Ping 并统计 PONG 与 RTT，连续 3 次没有回应就主动重连；写超时 10 秒，对端消失不会把线程永久挂死；状态栏直接显示 `fps · MB/s · 延迟 · 解码耗时`。

> 重要：本工具**没有加密、没有登录、没有鉴权**。同一局域网内能访问到端口的人都可以连接并控制被控端。仅在可信网络自用，不要暴露到公网，不用时关闭程序。

## 1. 快速开始

> **先解压，再运行**：不要把压缩包里的 `.bat` 直接双击。Windows 只会把 bat 临时解压出来，同目录没有 `lanlink.exe`，就会提示“找不到文件 lanlink.exe”。请先把整个 zip 解压到一个普通文件夹，再双击里面的 bat。

### 被控端（电脑 B，需要被控制的那台）

1. 把整个目录解压到一个可写位置，例如 `D:\LanLink`。不要只把 exe 放进 `C:\Program Files` 这类需要管理员权限的目录。
2. 如果 Windows 提示“已保护你的电脑”，点“更多信息 → 仍要运行”；或者右键 zip/exe → 属性 → 勾选“解除锁定”。exe 没有代码签名，这是正常提示。
3. 双击 `启动被控端.bat`。也可以手动运行：
   ```bat
   lanlink.exe --agent
   ```
4. 第一次运行，点击界面上的 **“放行防火墙（需 UAC）”**，在 UAC 弹窗点“是”。会添加两条入站规则：
   - TCP 47800，所有网络配置文件
   - UDP 47801，所有网络配置文件
5. 记下界面显示的局域网地址，例如 `192.168.120.120:47800`。窗口保持打开。
6. 如果需要控制 UAC 提权窗口，让被控端以管理员身份运行；普通权限只能控制普通窗口。
7. 双屏/多屏电脑：默认共享整个虚拟桌面（例如 3840x1080）。GDI 抓屏耗时和要拷贝的像素数几乎成正比，双屏下帧率大约只有单屏的一半。如果只需要共享主屏，用
   ```bat
   lanlink.exe --agent --primary-only
   ```
   实测同一台双屏机器：整个虚拟屏 3840x1080 是 16.8 fps（抓屏 61 ms），只抓主屏 1920x1080 是 36.2 fps（抓屏 32.9 ms）。

### 控制端（电脑 A，操作的那台）

1. 同样解压，双击 `启动控制端.bat`，或直接运行 `lanlink.exe`。
2. 点 **“扫描局域网”**，在结果里点设备右侧的“连接”；也可以直接在“目标”里输入 `192.168.120.120:47800` 后点“连接”。
3. 连接成功后看到 B 的桌面。**用鼠标点一下远程画面**，键盘输入才会发给 B（点画面同时会把窗口焦点抢回来）。
4. 顶部工具栏：
   - **连接 / 断开 / 立即重连**：「立即重连」= 立刻断掉当前会话再连一次（快捷键 F9）
   - **控制中 / 只看画面**：显示当前是否在发送键鼠。点一下切到「只看画面」，之后就只收画面、一个键鼠事件都不发（适合只想看进度、不想误操作别人的电脑）；再点一下恢复控制。画面左上角还有一个小徽标提示当前是只看画面。
   - **修复键鼠**（快捷键 F8）：远端键鼠突然不动时点它，会先软修复、无效则自动重连
   - **剪贴板同步**：双向文本/图片剪贴板
   - **发送文件**：选择本机文件发送到 B
   - **画质 / 帧率 / 最大宽度**：网络慢或 B 的 CPU 高时调低；帧率可调 1–60（默认 60，实际受抓屏速度限制）
   - **全屏 (F11)**
   - **释放键鼠**：远端按键卡住时点一下（会同时释放键盘和鼠标所有键）
   - 状态栏会实时显示 `fps · MB/s · 延迟 ms · 解码 ms`，以及 **`键鼠 注入 N`**（被控端累计注入成功的事件数；你操作时它不涨，说明事件没到被控端，界面会自动报警并修复）
5. 关闭控制端窗口或点“断开”即断开；B 端会自动释放残留按键。

## 2. VPN 场景说明

这是本工具专门处理过的场景，但要先理解边界。

### 为什么通常还能连

被控端监听的是 `0.0.0.0:47800`，不是某一个网卡。控制端连接的是 B 的**局域网 IP**（例如 `192.168.120.120`）。Windows 选路时遵循最长前缀匹配：同一网段的 `/24` 直连路由一般优先于 VPN 的 `0.0.0.0/0` 默认路由，所以流量仍然走 WiFi，不会进 VPN 隧道。

防火墙规则使用 `profile=any`，VPN 把网络切换成“公用网络”或新建一个网络配置文件时，入站规则仍然生效。

### 必须满足的条件

1. 两台电脑仍在同一个局域网/同一个 WiFi，B 的局域网 IP 没有变。
2. B 的防火墙允许 TCP 47800 入站（点过“放行防火墙”）。
3. VPN 客户端没有启用以下限制：
   - “禁止访问本地局域网 / Block local network access”
   - kill switch 把非隧道流量全部阻断
   - WFP 过滤器强制所有流量走 VPN
   - 某些企业 VPN 的“始终在线”策略

   这些是 VPN 客户端/驱动层的行为，应用层工具无法绕过，只能在 VPN 客户端设置里放开局域网，或把 `192.168.120.0/24` 加入排除/拆分隧道。
4. 路由器没有开启 AP 隔离/客户端隔离。

### 使用建议

- 先连 VPN，再启动或保持 LanLink 被控端运行，两者不冲突。
- 目标地址填 B 界面上显示的 `192.168.x.x:47800`，**不要填 VPN 分配给 B 的 `10.x` 地址**。
- 如果扫描不到，直接手动输入局域网 IP；UDP 广播可能被 VPN 或防火墙拦，TCP 直连通常仍然可用。
- 判断底层通不通：
  ```powershell
  ping 192.168.120.120
  Test-NetConnection 192.168.120.120 -Port 47800
  ```
  第二条 `TcpTestSucceeded : True` 就说明端口可达，问题在应用层；如果是 `False`，先查防火墙/VPN/网段。

## 3. 功能细节

### 剪贴板

- 两端都有“剪贴板同步”开关，任意一端关闭就不双向同步。
- 支持文本和图片；图片会编码成 PNG 传输。
- 复制后一般在 80ms 内同步（按剪切板序列号做廉价变更检测，未变化时几乎不耗 CPU）；写入对端后会抑制 700ms，避免两端来回回声。
- 在控制端按 Ctrl+V 时，程序会强制重读一次本地剪贴板并立刻推送，避免“粘贴发生在同步之前”的时序竞争；刚连上新连接时也会补推一次。
- 大图片或超大文本会让画面短暂卡顿，属正常。

### 文件传输

- 当前版本只支持**控制端 → 被控端**单向发送。
- 被控端保存目录会显示在界面上，优先级：
  1. `C:\Users\<用户名>\Downloads\LanLink`
  2. `C:\Users\<用户名>\LanLinkDownloads`
  3. `%LOCALAPPDATA%\LanLink\Downloads`
- 重名文件会自动改成 `文件名 (1).扩展名`，不会覆盖。
- 文件走独立的 TCP 连接，不阻塞控制通道；但大文件仍会占用带宽，可能降低画面帧率。

### 开机自启

- 被控端勾选“开机自动启动”，会写入当前用户的注册表：
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `LanLink`，命令为 `"<exe路径>" --agent`。
- 不需要管理员权限。
- 移动 exe 位置后需要重新勾选一次。

### 快捷键与输入

- 点一下远程画面即可获得键盘焦点；之后就算窗口焦点被别人抢走，也不会再像旧版那样「键盘鼠标一起死掉」——鼠标照常转发，键盘在 1.5 秒内会自动恢复（点画面、F8、或直接等自动修复）。
- **F8 = 修复键鼠，F9 = 立即重连，F11 = 全屏**。这三个键在控制端本地处理，不会发到被控端；其余按键照常转发。
- 键鼠是按**事件**转发的：只有在画面内按下、并且确实转发给被控端的键，抬起时才会转发抬起；在画面外、窗口失焦、切换窗口（Alt+Tab）时产生的指针/按键事件一律丢弃，并顺手释放远端可能残留的键。所以在窗口外乱点不会再在被控端冒出右键或让坐标漂移。
- 切换到「只看画面」后，控制端直接不发键鼠，被控端同时释放所有按下的键，不会出现“远端卡住某个键”的情况。
- **连按两次 Esc 退出远程控制**（断开连接并退出全屏），第一次按下时画面下方会提示“再按一次 Esc 退出远程控制”，400ms 内没有再按则自动取消。第一次 Esc 仍会正常发送给被控端；用于退出全屏/取消对话框时请按 F11 或界面按钮。
- 支持 Ctrl/Shift/Alt 组合键、字母、数字、方向键、F1-F12、Tab/Enter/Esc/Backspace/Delete/Home/End/PageUp/PageDown 等。
- Ctrl+C / Ctrl+X / Ctrl+V 单独处理：egui 会把它们转成「复制/剪切/粘贴」事件而不产生按键事件，程序负责翻译回真实的 Ctrl+C/X/V 发到被控端。
- Shift+数字会发送符号（`!@#$...`），不会重复。
- 中文等非 ASCII 文本通过 Unicode 注入发送，不依赖对端输入法；但某些 IME 候选窗、游戏反作弊、带保护的输入框可能不接收。
- **UAC 安全桌面、Ctrl+Alt+Del、锁屏界面无法采集/注入**，这是 Windows 的安全隔离，不是本工具的 bug。
- DRM 视频窗口、部分硬件加速/独占全屏程序可能捕获为黑屏。

## 4. 已知限制

- 仅 Windows 10/11 x64，仅 IPv4 局域网，默认要求同一网段。
- 多显示器默认合成为一个虚拟桌面（例如双屏 3840x1080），不是每个屏幕单独一路；被控端启动时加 `--primary-only` 可以只共享主屏（帧率大致翻倍），但不支持运行中切换。
- 没有音频传输。
- 剪贴板里是图片时，控制端按 Ctrl+V 不会额外补推（系统的粘贴事件只在剪贴板有文本时才产生）；图片本身仍会正常双向同步。
- 没有双向文件传输（只能 A → B）。
- 没有加密/鉴权，不能暴露在公网。
- 被控端必须在已登录的桌面会话中运行；锁屏/UAC 安全桌面/切换用户界面不可控。
- 被控端普通权限运行时，控制不了以管理员权限打开的窗口；需要被控端以管理员身份运行。
- 不提供服务化/开机未登录运行。

## 5. 故障排查

### 双击 bat 提示“找不到文件 lanlink.exe”

按顺序排查：

1. **没有先解压**：不要在压缩包预览窗口里直接双击 bat。Windows 只会把 bat 本身临时解压到 `%TEMP%`，`lanlink.exe` 不在那里。先把 zip 全部解压到一个普通文件夹（例如 `D:\LanLink`），确认 `lanlink.exe` 和 bat 在同一层，再运行。
2. **杀毒软件/Windows Defender 隔离了 exe**：这是未签名自用工具最常见的误报。打开“Windows 安全中心 → 病毒和威胁防护 → 保护历史记录”，找到 `lanlink.exe`，选择“还原”；再把解压目录加入“排除项”。公司电脑如果由 IT 策略强制拦截，应用层无法绕过。
3. **只复制了 bat，没复制 exe**：重新解压整个 zip，不要单独拖 bat 出来。
4. 在解压目录的地址栏输入 `cmd` 回车，执行 `dir lanlink.exe`，确认文件确实存在；再执行 `lanlink.exe --agent` 或 `lanlink.exe` 看是否报错。

### 被控端提示“监听 TCP 47800 失败（端口被占用？）”

已经有一个 LanLink 被控端在运行。关掉多余实例，或者用任务管理器结束旧的 `lanlink.exe`。查端口占用：
```powershell
netstat -ano | findstr :47800
```

### 控制端扫描不到设备

1. 确认两台电脑连的是同一个 WiFi/路由器，不是手机热点+另一个网络。
2. 确认 B 的界面显示“被控端运行中”，地址是 `192.168.x.x`。
3. 在 A 上手动输入 `B的IP:47800` 连接。
4. 在 B 上点“放行防火墙”，或手动执行：
   ```powershell
   netsh advfirewall firewall add rule name="LanLink TCP 47800" dir=in action=allow protocol=TCP localport=47800 profile=any
   netsh advfirewall firewall add rule name="LanLink UDP 47801" dir=in action=allow protocol=UDP localport=47801 profile=any
   ```
5. 路由器可能开了 AP 隔离，关闭“AP 隔离/客户端隔离”。
6. B 的 VPN 客户端可能禁止了本地局域网访问，按第 2 节处理。

### 能连上但画面黑屏/一直“等待远程画面”

- B 的桌面是否处于锁屏/UAC 安全桌面/DRM 播放器？这些无法捕获。
- B 是否有多显示器且主屏在休眠？唤醒屏幕。
- 试试把“最大宽度”调到 1280、“画质”调到 50。
- 看 B 的日志是否有 `BitBlt failed` 或 `capture` 错误。

### 键盘/鼠标没反应

先看控制端状态栏的 **`键鼠 注入 N`**，它直接告诉你问题在哪一层：

- **数字在涨，但被控端没反应**：事件已经注入到系统了，问题在被控端的目标窗口——最可能是权限不对（被控端普通权限，目标窗口是管理员权限），或者目标程序拦截了 SendInput（游戏反作弊、部分安全软件、UAC 安全桌面）。让被控端以管理员身份运行试试。
- **数字不涨，界面弹出红条**：控制端已经检测到键鼠通道卡住，**会自动修复**（先软修复，两次无效就自动断线重连），一般 1～2 秒自己就好了。想手动立刻修：按 **F8**（修复键鼠）或 **F9**（立即重连），工具栏上也有对应按钮。
- **什么都没发生，界面也没报警**：先点一下远程画面（或按 F8），再试。
- 被控端是否以普通权限运行，而要操作的窗口是管理员权限？让被控端以管理员运行。
- 远端按键卡住：按 F8，或点顶部“释放键鼠”；切到“只看画面”也会让被控端立刻释放。
- 游戏/反作弊/远程桌面类程序可能拦截 SendInput。
- 从 v4 起，重连一定会拿到干净会话（新连接会顶掉被控端上残留的旧会话），所以「断开再连一次」现在是真的有用。

### 文件发送失败

- 看 B 的日志里“接收文件到 …”后面的错误。
- B 的下载目录是否被“受控文件夹访问”/杀毒软件拦截？工具会自动降级到 `C:\Users\<用户名>\LanLinkDownloads`，界面会显示实际目录。
- 磁盘是否已满。

### 被控端 VPN 连上后断开

- 确认 A 连的是 B 的 `192.168.x.x`，不是 VPN 的 `10.x`。
- 在 B 上执行 `route print`，确认 `192.168.120.0/24` 仍然在“在链路上”的直连路由里。
- 如果 VPN 客户端有“允许本地局域网”选项，打开它。
- 如果 VPN 是全局强制隧道且不允许拆分，应用层无解。

## 6. 从源码构建

要求：Windows 10/11、Rust 1.92+（MSVC 工具链）、Git。

```powershell
cd lan-link
cargo build --release
```

产物：`target\release\lanlink.exe`。

仓库里的 `.cargo\config.toml` 使用 rsproxy 镜像；如果网络能直连 crates.io，可以删掉或改回默认。

自测（不需要第二台电脑，验证握手、视频帧、文件传输）：

```powershell
.\target\release\lanlink.exe --self-test
Get-Content .\_selftest.log
```

看到 `SELFTEST PASS` 即通过。自测会用端口 47890，不影响正式端口。自测现在还会验证「只看画面」开关确实能传到被控端、键鼠健康通道能收到 `InputStatus` 回执、以及接收端拿到的是脏瓦片增量而不是整帧。

抓屏基准（排查帧率用，会写 `_bench_capture.log`）：

```powershell
.\target\release\lanlink.exe --bench-capture
```

它会在本机测多组 BitBlt/StretchBlt 耗时，用来判断瓶颈在抓屏还是编码。

批量/脚本启动时想省掉手填 IP，可以设环境变量 `LANLINK_TARGET` 直接连过去（不设就是原来的空白界面）：

```powershell
$env:LANLINK_TARGET = "192.168.1.23:47800"; .\lanlink.exe
```

## 7. 技术结构（简）

```
src/
  main.rs       入口，--agent / --self-test / --bench-capture 分发
  app.rs        egui 界面、远程画面绘制（脏矩形局部上传）、键鼠事件映射与只读模式、双击 Esc 退出
  net.rs        TCP 控制/视频/文件、UDP 发现、FrameBoard 脏瓦片、心跳与 RTT、自动重连、防火墙/自启
  capture.rs    GDI DIB 双缓冲桌面捕获（虚拟屏或主屏）、区域变化检测、BGRA→RGB 缩放、抓屏基准
  pipeline.rs   被控端采集线程 + 并行编码线程（瓦片化增量帧、自适应画质、耗时统计）
  frame.rs      瓦片网格、KIND_VIDEO 负载格式（LFV2）、接收端画布
  input.rs      SendInput 键鼠/Unicode 注入（批量提交、完整释放、注入成功率统计）
  clipboard.rs  剪贴板序列号轮询、PNG 图片、回声抑制
  theme.rs      固定深色主题 + 显式调色板（对比度）、字号、面板/卡片边框、中文字体
  protocol.rs   帧格式与 JSON 消息（协议 v4）
  selftest.rs   本机端到端自测（含编解码、抓屏探测、只看画面、键鼠健康通道、脏瓦片增量）
```

- 控制连接：长度前缀帧，1 字节类型 + 4 字节大端长度 + payload；两端都开 TCP_NODELAY（TCP_QUICKACK 由系统处理），避免 Nagle 拖慢点击响应；读写都设了超时，对端消失不会把线程永久挂死。
- 画面：屏幕按“最大宽度”缩放到输出画布，画布切成 256x144 的瓦片；每帧只发送内容发生变化的瓦片（瓦片内 JPEG 独立编码）。接收端 `FrameBoard` 把瓦片拼进一张常驻画布并记下每个瓦片的矩形，UI 侧用 `TextureHandle::set_partial` **只上传变化的矩形**（脏瓦片超过 32 块或分辨率变了才整帧上传）——旧版每帧都要把整块 RGBA 画布 memcpy 成 `Vec<Color32>` 再重传整张纹理，1080p 下这是每帧 8.3 MB 的额外开销。
- 采集与编码在两个线程里跑：采集线程做 BitBlt + 逐瓦片 memcmp 变化检测，编码线程用 `thread::scope` 多线程并行编码变化的瓦片。两个线程之间用容量为 1 的 `sync_channel` + **阻塞发送**（旧版是 `try_send` + `sleep(1ms)` 忙等：既空转 CPU，又会在忙的时候丢掉带变化瓦片的 job，表现为残影）。帧按“间隔减去耗时”的方式节拍，不再额外叠加 sleep。
- 自适应画质：一帧里变化的瓦片占比越高，这一帧的 JPEG 质量越往下调（>75% 减 18、>45% 减 10、>20% 减 5，下限 30）；静止或只有小改动时仍按用户设的高画质发。拖窗口、放视频这类场景因此不会把带宽打满。
- 帧率上限 60（滑杆 1–60，默认 60）：帧率只是“节流上限”，实际帧率由抓屏速度决定。实测（12 线程 / 本地控制台 / 4.15 MP）：GDI 全屏 `BitBlt[SRCCOPY]` 约 50 ms，和像素数几乎成正比（1/4 面积只要 16–23 ms），编码 3.5–4.3 ms/帧、发送 2.2–2.4 ms/帧——**瓶颈完全在 GDI 抓屏**，不在编码和网络。所以：整个虚拟屏 3840x1080 ≈ 16.8 fps，只抓主屏 1920x1080 ≈ 36.2 fps。想再往上只能换 DXGI Desktop Duplication，本轮没做（需要手写 COM vtable，风险和收益不匹配）。
- 控制消息：JSON，鼠标归一化坐标（只在移动超过 0.03% 画布时发送），键盘用 Windows VK；滚轮按 120 的整数倍发 notch，不再直接转发像素 delta。
- 输入精准性：控制端按事件转发（`Event::PointerButton` / `MouseWheel` / `Key`），并记录“自己按下过哪些键/哪个鼠标键”，抬起只对记录内的生效；修饰键跟着每个按键事件自带的 `modifiers` 快照按顺序同步（按下时先同步修饰键再发键、抬起时先发键再同步修饰键），修掉 Ctrl+C 偶发变成裸 C 的问题。
- 只看画面：协议 v3 的 `ClientMsg::SetInput{enabled}`。被控端收到 false 立刻 `input::release_all()` 并停止注入，同时回一条 `Notice` 让控制端界面显示“已被控端确认”。
- 键鼠健康：控制端每 500 ms 发 `ClientMsg::InputProbe`，被控端回 `ServerMsg::InputStatus{session, received, injected, failed, gated, ok}`；控制端比较 `received` 是否增长、`ok` 是否为真，判定 `Stalled` / `Rejected` 两种故障。软修复 = `ClientMsg::ResyncInput`（被控端 `release_all()`）+ 控制端重新对齐按下的键 + 重新获取焦点；硬修复 = 立刻断线重连。同一时刻最多每 4 秒修复一次，避免抖动时反复打断。
- 会话顶替：被控端每个新连接拿一个自增会话号，并立刻 `shutdown` 上一个会话的 socket（旧版是 `busy` 拒绝新连接，旧连接卡住时重连会被拒）。控制端发现会话号变化就把健康计数清零。
- 断线：控制端每 1.2s 重连；每 3s 发 Ping 并统计 PONG 与 RTT，**连续 3 次没有回应就主动断开重连**（旧的 TCP 在断网后可能静默挂死）；被控端 8s 读超时后释放所有按键。
- 发现：UDP 47801 广播 `LANLINK_DISCOVER_V1`，被控端回复名称/端口/版本。


## 8. 安全提醒（再强调一次）

这个工具是给“自己的两台电脑、可信局域网”用的，设计上**故意没有做加密和鉴权**，换取简单和低延迟。任何能连到 47800 端口的人都可以看到屏幕、操作键鼠、读写剪贴板。不要在公司公共网、咖啡厅 WiFi、公网服务器上裸奔；不用时关闭被控端。
